From y = mx + c to Transformers to 1-bit

You remember the basics: weights, feed-forward, gradient descent, backprop. This guide rebuilds everything from the humble straight line, one concept at a time, until you can read Attention Is All You Need — and then see how BinaryLLM turns those same weight matrices into ±1 without training from scratch. Drag the sliders — every idea here is something you can poke.

START HERE

0 · How to read this

Every section introduces one new idea and reuses the idea before it. The chain is:

line → neuron → weighted sum → activation → layer (matrix) → stacked layers → learning → embeddings → attention (Q,K,V) → multi-head → transformer block → the full model → 1-bit weights → progressive F(x,t) → scales → Sign at inference
The single most important idea: a neural network is almost entirely matrix multiplication — which is just a huge pile of the w·x + b you already know, arranged in a grid. Everything else (activations, attention, layer norm) is decoration around that core. Hold onto that and the rest falls into place.
FOUNDATION

1 · The line: y = mx + c

Start with the equation you already know. A straight line takes one input x, scales it by a slope m, and shifts it by an intercept c:

y = m·x + c

m controls the tilt (how strongly x affects y). c controls the offset (where the line sits when x = 0). Drag them:

Notice: with two knobs you can only ever make a straight line. That limitation is exactly why we'll later need activations and many neurons.

FOUNDATION

2 · A line is a neuron

Now rename the parts. In machine learning we call the slope a weight w and the intercept a bias b. Same equation, new clothes:

y = w·x + b (was: y = m·x + c)

That's the whole story of a single-input neuron. The weight says "how much does this input matter, and in which direction?" A positive weight pushes the output up as x grows; a negative weight pushes it down. The bias sets the baseline.

Why "weight" is a good name: think of a decision like "should I go outside?" The input x = temperature. If you love warm weather, temperature has a big positive weight. The bias is your mood before you even look outside.

A neuron with one input is literally the line from Section 1. The leap to intelligence comes from giving it many inputs.

FOUNDATION

3 · Many inputs: the weighted sum

Real data has many features: pixels, words, sensor readings. Give the neuron several inputs x₁, x₂, …, xₙ, each with its own weight. The neuron multiplies each input by its weight, adds them all up, then adds one bias:

y = w₁·x₁ + w₂·x₂ + w₃·x₃ + … + wₙ·xₙ + b

This is the weighted sum (also called a "dot product" plus bias). It is the single operation repeated billions of times inside every large model. Play with a 3-input neuron:

FOUNDATION

4 · Activation: adding a bend

Stack a million weighted sums and you still only get… a bigger weighted sum. A line of lines is still a line. To model curves, decisions, and language, each neuron passes its weighted sum through a small non-linear function called an activation:

z = w₁x₁ + w₂x₂ + … + b (the weighted sum) a = activation(z) (the "bend")

Three you'll meet constantly:

  • ReLU — max(0, z). Negative? Output 0. Positive? Pass it through. Cheap and dominant in modern nets.
  • Sigmoid — squashes any number into (0, 1). Good for "probability-like" outputs.
  • tanh — squashes into (-1, 1). (Remember this one — it's the exact function BinaryLLM uses to smoothly turn weights into +1/-1.)

1.5

Without this bend, deep networks would collapse into one big line. The activation is what lets stacked layers represent genuinely complex functions.

NETWORKS

5 · A layer = a stack of neurons = a matrix

One neuron gives one output number. A layer is just several neurons looking at the same inputs, each with its own weights. Say 3 inputs and 4 neurons:

neuron 1: y₁ = w₁₁x₁ + w₁₂x₂ + w₁₃x₃ + b₁ neuron 2: y₂ = w₂₁x₁ + w₂₂x₂ + w₂₃x₃ + b₂ neuron 3: y₃ = w₃₁x₁ + w₃₂x₂ + w₃₃x₃ + b₃ neuron 4: y₄ = w₄₁x₁ + w₄₂x₂ + w₄₃x₃ + b₄

Look at the weights: they form a grid — a row per neuron, a column per input. That grid is a matrix W. The whole layer collapses to one compact line:

y = W·x + b

Here W is a 4×3 matrix (4 outputs, 3 inputs), x is a length-3 vector, b is a length-4 vector, and y is a length-4 vector. This is the exact same y = wx + b from Section 2 — just bundled. This single equation is what "linear layer", "dense layer", "projection", and "fully-connected layer" all mean.

A transformer's q_proj, k_proj, v_proj, o_proj, gate_proj, up_proj, down_proj are all exactly this: y = W·x. When a paper says "binarize the linear layers," it means "replace the numbers inside these W matrices with just +1/-1." Now you know what they're talking about.
NETWORKS

6 · Matrix × vector, made visual

Matrix multiplication sounds scary; it's just "one dot product per output row." Each row of W pairs up with the input vector, multiplies element-by-element, and sums. Watch it happen row by row:

Matrix–vector multiply (W · x)

The highlighted row of W is being dotted with x to produce the highlighted output. This is the engine of every layer.

A layer with 1536 inputs and 1536 outputs (Iris's hidden size) is a 1536×1536 matrix — about 2.4 million weighted sums for a single token. Multiply that by dozens of layers and millions of tokens and you see why we care so much about shrinking those numbers.

NETWORKS

7 · Stacking layers → a multi-layer network (MLP)

Feed the output of one layer into the next. Between layers, apply an activation so the stack doesn't collapse into one line. That's a multi-layer perceptron — the classic feed-forward neural network:

h₁ = activation(W₁·x + b₁) ← hidden layer 1 h₂ = activation(W₂·h₁ + b₂) ← hidden layer 2 y = W₃·h₂ + b₃ ← output layer

"Feed-forward" just means information flows left to right, layer to layer, no loops. Watch a signal propagate through a small network — each edge is a weight, each node runs a weighted sum + activation:

Forward pass through a 3-4-4-2 network

Depth = abstraction. Early layers detect simple patterns; later layers combine them into complex concepts. The same principle scales from 3 neurons to billions of parameters.
NETWORKS

8 · How the model learns (loss, gradients, backprop)

So far the weights were random. Training is the process of nudging them until the output is right. Three moving parts:

  1. Loss — a number measuring how wrong the prediction is. Bigger = worse. For a line, a common choice is squared error: (prediction − target)².
  2. Gradient — for each weight, "if I increase this weight a tiny bit, does the loss go up or down, and how fast?" That's the slope of the loss with respect to that weight.
  3. Gradient descent — step every weight a little in the direction that reduces loss: w ← w − learning_rate · gradient. Repeat.

Backpropagation is just the efficient recipe (the chain rule from calculus) for computing all those gradients in one backward sweep, from the loss back through every layer. Watch gradient descent fit a line to noisy points — each click takes one step downhill:

Gradient descent fitting a line

0.030

Too small a learning rate → crawls. Too big → overshoots and diverges. Finding this balance is a core part of training real models.

You now have the entire foundation: weighted sums arranged as matrices, bent by activations, stacked into layers, and tuned by gradient descent. Everything from here — including transformers — is built only from these pieces. The rest is clever wiring.
TOWARD TRANSFORMERS

9 · Language is a sequence — and order matters

An MLP takes a fixed bag of numbers and produces an answer. But a sentence is a sequence of words, and each word's meaning depends on the others:

"The animal didn't cross the street because it was too tired."

What does "it" refer to? To know, the model must let "it" look at the other words and decide which ones matter. That looking-and-weighing is attention.

The plan for the rest of the guide:

1. Turn each word into a vector of numbers (embeddings, §10) 2. From each vector, build 3 new vectors: Q, K, V (projections, §11) 3. Every word scores every other word (Q·K, §12) 4. Turn scores into weights, blend the V's (softmax, §13) 5. Do it several ways at once (multi-head, §14) 6. Tell the model word order (positions, §15) 7. Add an MLP + wiring to finish the block (§16) 8. Stack the blocks (§17)

Notice steps 1–4 are only matrix multiplies and one softmax. You already know matrix multiplies.

TOWARD TRANSFORMERS

10 · Embeddings — words become vectors

Computers can't multiply the word "cat." So we assign every token (word or word-piece) a learnable vector of numbers — its embedding. The embedding table is one giant matrix: one row per vocabulary item.

"cat" → [ 0.21, -0.44, 0.90, ... ] (length = hidden size, e.g. 1536) "dog" → [ 0.19, -0.40, 0.85, ... ] "car" → [-0.72, 0.11, -0.33, ... ]

Similar meanings end up as nearby vectors. In a real model the embedding table dominates the file size when the vocabulary is huge — Iris has 130,560 tokens × 1536 dims, which is why that one table is ~400M of the model's ~1B parameters.

Word vectors in 2D (distance ≈ similarity)

These toy 2D embeddings cluster related words. Real embeddings live in hundreds or thousands of dimensions, but the intuition is identical: direction and distance encode meaning.

TOWARD TRANSFORMERS · THE BIG ONE

11 · Query, Key, Value — three projections

Here is the idea people find mysterious, made concrete. From each word's embedding x, we create three new vectors by multiplying it through three different weight matrices — three linear layers exactly like Section 5:

Q = W_q · x ← the "Query" : what am I looking for? K = W_k · x ← the "Key" : what do I offer/advertise? V = W_v · x ← the "Value" : what content do I carry?

A librarian analogy that actually maps onto the math:

  • Query = your search request at the desk ("books about space").
  • Key = the label on each book's spine (what it advertises itself as).
  • Value = the actual contents inside the book.

You match your query against every key to decide relevance, then you actually read the values of the books that matched — weighted by how well they matched.

The crucial point: W_q, W_k, W_v are just weight matrices, learned by gradient descent (Section 8). The model discovers on its own what makes a good query, key, and value. "Projection" simply means "multiply by a matrix to get a new vector" — nothing more.

TOWARD TRANSFORMERS

12 · Attention scores — every word rates every word

Now we measure relevance. Word i compares its query Qᵢ against word j's key Kⱼ using — you guessed it — a dot product (Section 3). A big dot product means "these two are aligned; j is relevant to i."

score(i, j) = Qᵢ · Kⱼ (a single number) scaled = (Qᵢ · Kⱼ) / √d_k (keep numbers from exploding)

Do this for every pair and you get a grid of scores — the attention matrix. Row i tells you how much word i wants to pull from each other word. The √d_k division just stops the dot products from getting so large that the next step (softmax) becomes too "spiky."

Attention score grid for a short sentence

Brighter = higher score = "this word is paying more attention to that word." Hover a cell.

TOWARD TRANSFORMERS

13 · Softmax → weights, then blend the Values

Raw scores can be any size. Softmax turns each row of scores into positive weights that sum to 1 — a clean set of "attention percentages." It exponentiates each score and divides by the total:

softmax(s)ⱼ = e^(sⱼ) / Σ e^(sₖ) → weights that add up to 1.0

Then the new representation of word i is a weighted sum of all the Value vectors, using those attention weights. (Weighted sum again — the very first idea from Section 3.)

output_i = Σⱼ attention_weight(i,j) · Vⱼ

So each word rebuilds itself as a blend of the words it decided were relevant. That's the entire mechanism. Play with raw scores and watch softmax convert them into a blend:

TOWARD TRANSFORMERS

14 · Multi-head attention — several views at once

One attention pattern can only capture one kind of relationship. Real language has many at once: grammar, subject-verb links, long-range references. So we run attention several times in parallel, each with its own W_q, W_k, W_v — these parallel copies are heads.

head 1: attention with (W_q¹, W_k¹, W_v¹) → focuses on, say, syntax head 2: attention with (W_q², W_k², W_v²) → focuses on, say, references ⋮ concat all heads → multiply by W_o (output projection) → final result

Each head is cheaper (it works on a slice of the dimensions), they run independently, then their outputs are concatenated and mixed by one more linear layer W_o. Toggle heads and watch different attention patterns light up:

TOWARD TRANSFORMERS

15 · Positional encoding — telling the model about order

Attention treats the input as a set — it has no built-in sense of "first word vs. last word." But "dog bites man" ≠ "man bites dog." So we add position information to each embedding before attention.

The original paper uses sine and cosine waves of different frequencies; each position gets a unique fingerprint that the model can read off:

PE(pos, 2i) = sin( pos / 10000^(2i/d) ) PE(pos, 2i+1) = cos( pos / 10000^(2i/d) ) input = embedding + PE (just add them together)

Each column below is one position's encoding — a unique pattern of values the network learns to interpret as "where am I in the sentence."

Positional encoding fingerprints

Rows = dimensions (low = fast waves, high = slow waves). Columns = positions. Every column is distinct, so the model can always tell positions apart. Modern models often use rotary variants (RoPE), but the goal is the same.

TOWARD TRANSFORMERS

16 · The feed-forward network & the transformer block

After attention has let words share information, each word is passed independently through a small MLP (Section 7) to "think" about what it gathered. This is the feed-forward network (FFN): expand to a bigger hidden size, apply an activation, shrink back.

FFN(x) = W_down · activation(W_up · x) (two linear layers + a bend)

Two more pieces of wiring hold everything together and make deep stacks trainable:

  • Residual connection — add the input back to the output: x + sublayer(x). Gives information a "shortcut" so gradients flow cleanly through many layers.
  • Layer normalization — rescale each vector to a stable range so numbers don't blow up or vanish.

Assemble it and you get one transformer block:

x → LayerNorm → Multi-Head Attention → (+ x) → LayerNorm → Feed-Forward Network → (+ x) → out

Anatomy of one transformer block

The two "+" nodes are residual adds; each colored box is either attention or the FFN, wrapped in normalization. Every linear box inside is a W·x — the matrices a compression method like BinaryLLM targets.

THE WHOLE THING

17 · The full architecture (Attention Is All You Need)

Stack N identical transformer blocks, wrap them with embeddings at the bottom and a prediction head at the top, and you have a complete model:

End-to-end: tokens in, next-word probabilities out

Reading it bottom-to-top, every stage is now something you understand:

  1. Tokenize — split text into tokens (word-pieces).
  2. Embed (§10) — each token → a vector, via a lookup matrix.
  3. Add positions (§15) — inject word order.
  4. N × transformer blocks (§16) — each does multi-head attention (§11–14) + FFN, with residuals and norms.
  5. Output head — a final linear layer (§5) maps the top vector to a score for every vocabulary word.
  6. Softmax (§13) — turn those scores into probabilities; pick the next token.
Zoom all the way out: the entire model is W·x + b repeated in enormous grids, bent by activations, wired with attention and residuals, and tuned by gradient descent. The line you started with in Section 1 never left — there are just billions of them now, cooperating.
What comes next: those billions of floats are expensive to store and multiply. Sections 18–25 show how BinaryLLM converts the linear-layer weights inside each block into ±1 — while keeping the architecture you just learned intact.
BINARY WEIGHTS

18 · Why compress? Memory and multiplies

A 7B model in FP16 needs roughly 14 GB just for weights. Most of that is the linear matrices you met in §11 and §16. If every weight becomes a single bit (±1), weight storage drops by about 16× vs FP16 — and float multiplies become cheap add/subtract (or bit ops on hardware that supports them).

Embeddings and the final output head are usually left at higher precision (large, sensitive). The compression target is the linear layers inside transformer blocks.

Same 8×8 weight matrix — two storage stories

Goal: keep the same transformer you built in §17, but store (and multiply with) binary weights for every W inside the blocks.
BINARY WEIGHTS

19 · What “1-bit” means: Sign and {−1, +1}

Full-precision weights are continuous floats. 1-bit quantization maps each weight to only two values:

Sign(w) = +1 if w ≥ 0 = −1 if w < 0

That alone loses magnitude — a weight of 0.01 and a weight of 3.7 both become +1. So real binary nets also keep a small scale (next sections). For now, poke a tiny weight grid and watch Sign snap every entry:

Float weights → Sign → binary grid

Paper notation: X_b = S_a × Sign(X). The scale S_a puts the size back; Sign only keeps the direction.
BINARY WEIGHTS

20 · Why Sign on day 0 destroys a pre-trained LLM

Pre-trained weights are already at a good minimum — tiny changes matter. If you slam Sign(W) onto them at the start of training, you trash that distribution. The paper shows the initial loss jumps near ~10 — almost like training from scratch.

Higher bit-widths hurt less; ultra-low bit (1 / 1.58 / 2) is where the cliff appears. That is why “just Sign and fine-tune” is not enough for LLMs.

BINARY WEIGHTS · THE BIG ONE

21 · Progressive F(x, t) — soft morph into Sign

BinaryLLM’s core idea: replace hard Sign during training with a smooth function that starts nearly linear and ends near Sign:

F(x, t) = tanh(t · x) / tanh(t) lim t→0 F(x,t) ≈ x (almost identity — keep pre-trained W) lim t→∞ F(x,t) ≈ Sign(x) (fully binary)

t is a schedule that grows during training. Crucially, the same F is used in forward and backward (consistent progressive training) — unlike older binary nets that Sign in forward and only soften the gradient.

Training uses W_b = S_a × F(W / S_a, t). At the end, swap F for Sign with almost no extra error — because F already looks like Sign.
BINARY WEIGHTS

22 · Putting magnitude back: scale Sa

±1 alone has no size. The analytical scale that minimizes L2 error between W and a binary copy is the mean absolute value:

S_a = (1/n) Σ |W_i| W_b = S_a × F(W / S_a, t)

Dividing by S_a before F keeps the progressive curve in a sensible range; multiplying back restores magnitude so the layer still produces outputs of the right scale.

23 · Dual scaling: Sa × Sl

Even with progressive F, residual error remains. BinaryLLM keeps two scales:

  • S_a — fixed analytical scale (mean |W|) that keeps quantization error small at every step
  • S_l — learnable, initialized to 1, updated during training to recover accuracy
W_b = S_l × S_a × F(W / S_a, t)

Using only a learnable scale (and dropping the analytical one) hurts LLMs — the paper’s ablations show dual scaling wins. At inference the two merge: S = S_l × S_a.

Toggle which scales are active

Binary-aware initialization (paper §3.3) is a short pre-search for channel scales that protect salient weights before progressive training starts — a warm-up so hard bits hurt less. The dual scales above are what you see every training step.
BINARY WEIGHTS

24 · Train with F · serve with Sign

During training the model sees soft binary weights. For deployment you want pure ±1 and one merged scale — no tanh at runtime:

train: W_b = S_l × S_a × F(W / S_a, t) inference: W_b = S × Sign(W) where S = S_l × S_a

Because t ends large, F ≈ Sign, so the swap is nearly free. Multiplies become additions of ± scaled activations.
